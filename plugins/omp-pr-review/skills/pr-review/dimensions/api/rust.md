# API — Rust
## Flag
- Trait method added without a default body to a `pub` trait that downstream crates implement — breaks every external `impl`. Not a break if the trait is sealed (private supertrait/`mod private`) or only implemented in-crate. Adding a method *with* a default is minor but can cause ambiguity with a same-named method from another trait (flag only with a named conflict).
- Enum: new variant added to a `pub enum` without `#[non_exhaustive]` — downstream exhaustive `match` fails. Same for struct fields: adding a `pub` field to a struct whose fields are all pub (struct literal/pattern use breaks), or adding any field to a tuple struct with all-pub fields. Adding `#[non_exhaustive]` itself to an existing type is a breaking change. `#[non_exhaustive]` only binds other crates; in-crate matches are unaffected.
- Removing or renaming a `pub` item, changing a `pub` fn signature, changing generic parameters/bounds (tightened bounds break callers; added type parameter without default breaks turbofish/inference), changing `&self` ↔ `&mut self`/`self`, removing a public `impl`/derive (`Clone`, `Debug`, `PartialEq`, `Hash`, `Default`, `Serialize`).
- Auto-trait regression: a pub type becomes `!Send`/`!Sync`/`!Unpin` or non-`UnwindSafe` (adding `Rc`, `Cell`, raw pointer, `MutexGuard`, non-Send `dyn Trait`) — breaks users spawning it on threads/tokio tasks. Same for `impl Trait` return types leaking an auto trait. Check the new field/type's auto traits.
- Blanket `impl<T: Bound> Trait for T` added to a pub trait, or a new impl of a foreign/pub trait for a generic type — can conflict with downstream impls (coherence); report only with a concrete downstream impl shape or when it is a well-known conflict (e.g. blanket over `T: Display`).
- Return/param type changed to a type from a dependency whose version bumped across a semver-major boundary (types re-exported in the public API) — downstream must unify versions. Check public signatures that mention the dependency.
- Cargo features: feature removed/renamed, or a default feature dropped; features that are non-additive (enabling one disables functionality / changes types, `cfg(not(feature = ...))` selecting alternative APIs) — features are unified across the dependency graph, so non-additive features break builds. Making an optional dependency required changes its implicit feature.
- `rust-version` (MSRV) raised, or code uses syntax/stdlib newer than the declared `rust-version`/CI MSRV job, or edition bumped to 2024 in a published crate — check the crate's stated MSRV policy in README/CHANGELOG before reporting; many crates treat MSRV bumps as minor.
- Edition 2024 hazards: `impl Trait` return types capture all in-scope generics/lifetimes by default (changes borrowck for callers); `unsafe extern` blocks, `unsafe_op_in_unsafe_fn` warn-by-default, `gen` reserved keyword (identifier named `gen` in a public item breaks), `static mut` references denied, tail-expression temporary drop order changes. Flag only when the diff migrates edition and the change reaches the public API or drop-order-sensitive code.
- Layout/ABI: `#[repr(C)]` struct/enum layout, `extern "C"` signatures, `#[no_mangle]` names, cbindgen/`.h` output changes, FFI-exposed enum discriminants reordered; `#[repr(u8)]`/explicit discriminants changed on types serialized as integers.
- Serde formats: `#[serde(rename/rename_all/tag/content/untagged)]`, `#[serde(default)]` removal, field renamed without `alias`, enum representation changed, `deny_unknown_fields` added — alters wire/persisted compatibility. Variant reorder matters for non-self-describing formats (bincode/postcard).
- CLI (`clap`): flag/subcommand/`env` name changed, `value_enum` variant renamed, default changed, `required` toggled, `arg_required_else_help`; exit code / `--help` machine parsing.
- Error type changes: `pub enum Error` variant payload changed or `From` impls removed — breaks `?` conversions and matches downstream.

## Safe (do not flag)
- `pub(crate)`, `pub(super)`, private modules, items not reachable from the crate root re-exports (`pub use`), binaries (`src/main.rs`-only crates) and `[[bin]]` internals.
- Adding new pub items, new inherent methods, new variants to `#[non_exhaustive]` enums, new fields to `#[non_exhaustive]` structs, new trait methods with defaults, new `impl`s of the crate's own trait for new types.
- Adding a trait impl for a new type, or `#[derive]`s to existing types.
- `0.x` crate version with a minor bump documenting the break (Cargo's semver treats `0.y` bumps as breaking); workspace-internal crates with `publish = false` and all dependents updated.
- Loosening bounds, widening accepted input (`&str` → `impl AsRef<str>` is mostly safe except inference at call sites with literals — flag only with a concrete failing call).
- Changes to `#[cfg(test)]`, benches, examples, doc-hidden items (`#[doc(hidden)]` is not API by convention, unless the crate documents otherwise).
- Lockfile churn; bumping dependency within a compatible range.
